# ADR-0014 — Native financial report documents

- Status: Accepted (statutory templates pending approval)
- Date: 2026-11-10
- Deciders: Architect + product owner (DEC-029, DEC-040)

## Decision

Existing authorized and branch-scoped report export endpoints accept `format=csv|xlsx|pdf`; CSV remains the compatibility default. They also accept `language=ar|en|bilingual` for PDF direction and document language. Browser print remains supported.

All formats are produced from the same canonical report rows and decimal strings. XLSX is a native OOXML workbook generated by OpenSpout. PDF is rendered locally by Dompdf with remote and PHP execution disabled and a Unicode font. Synchronous detail exports remain capped at 50,000 rows, and every export retains the existing audit event and `reports.export` permission.

## Consequences

- Arabic and English data are retained in each export; PDF direction follows the selected language.
- No statutory wording, signature, or jurisdiction-specific template is asserted until approved.
- Larger future workloads require a separately authorized queued export design.

## Trial balance CSV layout

The trial balance CSV (`/reports/trial-balance/export`) has a fixed header, in
this order:

| # | Column | Notes |
|---|--------|-------|
| 1 | `Code` | Chart-of-accounts code |
| 2 | `Name (EN)` | English account name |
| 3 | `Name (AR)` | Arabic account name |
| 4 | `Opening debit` | Decimal string in the report currency |
| 5 | `Opening credit` | Decimal string |
| 6 | `Debit` | Period movement |
| 7 | `Credit` | Period movement |
| 8 | `Closing debit` | Decimal string |
| 9 | `Closing credit` | Decimal string |
| 10 | `Abnormal` | `Yes` when the closing side is abnormal for the account type, otherwise blank |
| 11 | `Currency` | Report currency code |

The final row is a `Total` row: `Code` and `Name (EN)` are blank and the
amount columns carry the report totals. `Abnormal` was introduced after the
first release; consumers that index columns by position should switch to
reading the header row.

## Addendum 2026-11-12 — export reliability hardening

- Reports build typed rows once (`ReportCsv::*Rows`); CSV, XLSX and PDF render the same rows.
  Money is carried as exact decimal strings from integer minor units and written as numeric XLSX
  cells with a number format for the currency exponent (values above 15 significant digits stay
  text). Dates are real date cells. Text is always an explicit string cell; text beginning with
  `=`, `+`, `-`, `@`, tab, CR or LF is prefixed with an apostrophe in every format.
- PDF: Dompdf with the DejaVu Sans font shipped by the `dompdf/dompdf` dependency (no remote
  fetch, `isRemoteEnabled` off, only `data:` URIs allowed). Arabic is shaped to Presentation
  Forms-B and reordered visually by `ArabicText` (Dompdf has no shaping/bidi); paragraph direction
  follows the first strong letter of each cell. Letterhead (logo, company names, branch, period,
  currency, timestamp in the installation time zone), repeated column header, and "page n / N" appear
  on every page. The sign-off line is controlled by `general.report_signoff` (default on). The
  logo comes from `general.company_logo` (PNG/JPEG path under `storage/app` or `data:` URI; other
  values are ignored). PDF output is capped at 5,000 rows (422); use CSV or XLSX beyond that.
  Limitation: Persian/Urdu-only letters are not shaped.
- Throttle: named limiter `report-exports`, 20 per minute per user, PDF additionally 6 per minute.
  The previous unnamed `throttle:20,1` shared its counter with other `throttle:N,1` routes.
- Format and language are validated before the report runs and before the audit event, which now
  records report, format, language, branch, row count and filters (no party names or amounts).
- Fixed-asset reports gained exports (`/reports/fixed-assets/{report}/export`), requiring both
  `assets.view` and `reports.export`.
- Not changed: statutory tax-invoice templates remain `PENDING_ACCOUNTANT_APPROVAL`; no queued or
  streamed export exists, so the synchronous 50,000-row cap stands. Bank reconciliation has no
  export yet.

## Addendum 2026-11-12 ? invoice and credit-note documents

- `GET /api/v1/invoices/{invoice}/pdf` renders the stored invoice, supplier bill or credit note as
  an A4 portrait PDF. It requires `invoices.view`, is branch-scoped, and is throttled by the
  `report-exports` limiter. `language=ar|en|bilingual` defaults to `documents.default_language`.
- Content: company letterhead (`general.company_name_ar`, `general.company_name_en`,
  `general.company_logo`), branch, document type and number, status, issue/due dates, currency,
  FX rate with rate date when the invoice is in a foreign currency, booking reference, the
  invoice it credits, bill-to/supplier block, line items (description, quantity, unit price, tax,
  amount), subtotal/tax/total/paid/amount due (or credited/applied/remaining credit for a credit
  note), memo, and sign-off lines. Page numbers are drawn after layout.
- Draft, submitted, approved and voided documents carry an explicit status band (draft and void
  also state that the document must not be paid). Issued documents carry no band. This is not a
  statutory tax-invoice template; DEC-028 remains open and the document is generic per install.
- Rendering is read-only: no journal is posted, revalued or mutated. Audit event `invoice.exported`
  records type, number, language and branch only.
- The letterhead logo loader is shared with report PDFs (`App\Support\LogoDataUri`): PNG/JPEG only,
  no remote fetch, no path outside `storage/app`, 1 MiB cap. Arabic shaping is shared through
  `App\Support\ArabicText`. Limitation: Persian/Urdu-only letters are not shaped.
- The invoice profile downloads this endpoint (`?language=<current UI locale>`) instead of calling
  `window.print()`. Blob downloads share `web/src/lib/download.ts` with report exports.
  `web/e2e/invoice-pdf.spec.ts` covers the browser flow: sign in, open an invoice, download, and
  assert the PDF signature and server-suggested filename.

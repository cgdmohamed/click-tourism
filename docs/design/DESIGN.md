# Tourism ERP theme

## Overview

Default token theme for the UI Colors Design Token Builder, adapted for the Tourism ERP application. This is a token-driven interface with coordinated light and dark color modes. The structured tokens above are the normative source of truth.

## Fonts

The original theme specified Inter for interface text and Mona Sans for display text. The client supplied **Suisse Intl** (Regular 400, Medium 500, Semibold 600, Bold 700) and it is now the single brand family for **both Arabic and English**. The supplied files include Arabic glyphs, Arabic presentation forms, and GSUB/GPOS shaping tables, so no separate Arabic family is required.

- Font files are self-hosted from `web/src/assets/fonts/` and loaded with `@font-face` in `web/src/index.css`.
- The fallback stack is `"Suisse Intl", "Noto Sans Arabic", ui-sans-serif, system-ui, sans-serif`.
- Interface text and display text both use the `--font-sans` / `--font-display` tokens.
- Numeric rendering is forced to lining figures. The Arabic locale uses the `ar-EG-u-nu-latn` numbering system so dates and money always display Western digits `0123456789`.

## Colors

The primitive palettes are Zinc, Purple, Orange, Green, Red, Blue, Cobalt. Semantic roles cover Surface, Text, Border, Primary, Secondary, Success, Warning, Danger, Info, Chart, Brand 1, Brand 2, Brand 3.

Use unsuffixed semantic color tokens for light mode and the matching `-dark` token for dark mode. Components should consume semantic colors instead of primitive palette values so that intent and theming remain intact.

The application maps the semantic roles into Tailwind v4 `@theme` tokens and activates the dark values under `prefers-color-scheme: dark`. Compatibility aliases (`surface`, `canvas`, `line`, `ink`, `muted`, `positive`, `negative`, `warning`, `brand-*`) resolve to the semantic roles; new components should prefer the full semantic names.

## Typography

Use `'Suisse Intl', sans-serif` for all interface and display text. Available complete text styles are `display-large`, `display-medium`, `display-small`, `heading-large`, `heading-medium`, `heading-small`, `text-large`, `text-medium`, `text-small`, `label`. Apply each style as a unit so family, size, weight, line height, and letter spacing stay synchronized.

Preserve the authored casing of text; the current styles do not apply a text transform.

## Layout

Use the `size-*` spacing scale for dimensions and gaps. Current form layout uses these resolved values:

- Field group gap: 1.75rem
- Field control gap: 0.75rem
- Field content gap: 0.25rem

No grid, breakpoint, container-width, or responsive-layout rules are encoded in the current tokens.

## Elevation & Depth

Elevation uses the following CSS-compatible shadow recipes. Shadows live in prose because the current DESIGN.md alpha schema has no structured top-level shadow group.

- `shadow-1`: `0px 1px 2px 0px color-mix(in srgb, oklch(0.141 0.005 285.823) 5%, transparent)`
- `shadow-2`: `0px 1px 3px 0px color-mix(in srgb, oklch(0.141 0.005 285.823) 10%, transparent), 0px 1px 2px -1px color-mix(in srgb, oklch(0.141 0.005 285.823) 10%, transparent)`
- `shadow-3`: `0px 4px 6px -1px color-mix(in srgb, oklch(0.141 0.005 285.823) 10%, transparent), 0px 2px 4px -2px color-mix(in srgb, oklch(0.141 0.005 285.823) 10%, transparent)`
- `shadow-4`: `0px 10px 15px -3px color-mix(in srgb, oklch(0.141 0.005 285.823) 10%, transparent), 0px 4px 6px -4px color-mix(in srgb, oklch(0.141 0.005 285.823) 10%, transparent)`
- `shadow-5`: `0px 20px 25px -5px color-mix(in srgb, oklch(0.141 0.005 285.823) 10%, transparent), 0px 8px 10px -6px color-mix(in srgb, oklch(0.141 0.005 285.823) 10%, transparent)`
- `shadow-6`: `0px 25px 50px -12px color-mix(in srgb, oklch(0.141 0.005 285.823) 25%, transparent)`

## Shapes

Use the `radius-*` tokens from the frontmatter. Component-specific radius choices are captured in the structured component tokens and should remain consistent within each component family.

## Components

- **Buttons:** Use the `label` text style, a 2.25rem height, 0.75rem radius, and 1rem horizontal padding. Primary and secondary interaction colors come from their matching semantic action tokens. Destructive actions use the secondary surface with `danger-border` / `danger-text` and a `danger-background` hover, because the current token set does not define a separate danger action role.
- **Inputs:** Use the `text-medium` text style, a 2.25rem height, 0.75rem radius, 0.75rem horizontal padding, and the `border-default` border treatment.
- **Cards:** Use 1.5rem internal spacing, 1rem between child elements, a 1rem radius, and `shadow-2` for elevation.
- **Popovers:** Use 0.5rem internal spacing, a 1rem radius, the `border-subtle` border color, and `shadow-4` for elevation. Use the default surface background for dropdown menus and popovers.
- **Badges:** Use a 0.375rem radius and the matching success/warning/danger/info background, border, and text tokens.

Border colors and shadow assignments remain documented here rather than in component frontmatter because those property names are not part of the current DESIGN.md alpha component schema.

## Do's and Don'ts

- Do use semantic color tokens for component styling.
- Do switch all semantic color roles together when changing color mode.
- Do apply typography tokens as complete styles.
- Do keep Western digits `0123456789` in both locales.
- Don't replace semantic colors with primitive palette values inside components.
- Don't invent brand, layout, motion, or accessibility rules that are not yet documented.

## Implementation notes

- Tokens are defined in `web/src/index.css` with Tailwind v4 `@theme static` so every token is emitted, including the `-dark` variants.
- Light mode uses the unsuffixed token. A `prefers-color-scheme: dark` block maps each semantic role to its `-dark` value.
- Typography classes (`display-large`, `heading-large`, `text-medium`, `label`, etc.) are complete style units in the components layer.
- `rounded-*` utilities come from the numeric `radius-*` tokens (`rounded-12`, `rounded-16`, `rounded-6`).
- `shadow-1` through `shadow-6` utilities come from the shadow recipes above.
- The spacing scale maps to Tailwind's existing spacing utilities: `size-16` = 1rem = `p-4`, `size-24` = 1.5rem = `p-6`, and so on.

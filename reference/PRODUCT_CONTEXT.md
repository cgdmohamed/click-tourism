# PRODUCT CONTEXT — REQUIRED FOR ALL AGENTS

Product: Self-hosted Tourism ERP for deployment on a separate server per customer. ONE product codebase, separately configured installations. NOT SaaS, NOT multi-tenant. Customer-specific hardcoding and per-client forks are forbidden. First reference project is Safe Way, but use neutral branding and configurable settings.

Baseline stack: Laravel API (PHP), React + TypeScript + Vite, Tailwind + existing user-supplied Design System, PostgreSQL, Redis, Docker Compose, GitHub Actions. Use versions that are verified compatible with repository lockfiles; do not automatically upgrade. Laravel Sanctum for auth; Spatie Permission and Laravel policies for authorization when appropriate. Modular monolith, no microservices.

IMPORTANT: The user has an existing DESIGN SYSTEM ONLY. It is NOT a finished UI, and no repo/design tokens have yet been provided in this package. Locate and audit that system in the project before proposing implementation. Do not redesign or overwrite it. Implement application screens from product flows using existing design tokens/components. If missing, document the gap and extend consistently; do not invent a parallel UI kit.

Core scope: double-entry accounting, chart of accounts, journal entries, cash/bank, expenses, opening balances, fiscal years/closing; multiple currencies EGP/SAR/USD and editable FX rates per transaction; suppliers (flight/hotel/transport/visa/agents), customers, multi-service bookings, partial payments, refunds/cancellations, booking profitability and commissions; financial reports (GL, trial balance, income statement, balance sheet, aging), PDF export; configurable tax; CRM (Meta lead forms, WhatsApp, manual, CSV/Excel), lead assignment rules and 24h follow-up reassignment, configurable pipeline, branch/user sales reports; roles and branch scopes; CSV/Excel import/export; RTL Arabic + English and responsive web. Web only. External API credentials/fees are out of scope.

Security and correctness: no floats for money, use DECIMAL/NUMERIC + currency minor units; journal postings balanced and immutable, corrections via reversals; idempotent business actions and webhook ingestion; policy checks on all endpoints; audit trail; sensitive data redaction; timezone-aware timestamps; backup/restore and migration verification. No production secrets. Financial business rules require accountant validation; explicitly mark unresolved interpretations as decisions to be approved.

WORK STYLE: Inspect existing repo and project docs first. Do not overwrite pre-existing code or design system. Make a short plan, implement the requested slice, add tests, run relevant checks, explain changed files and commands, identify unresolved issues. Work on issue-scoped branch/worktree; never force-push or commit directly to main. No invented integrations or fake production success. If prerequisite is absent, create a contract/mock and explicitly identify the dependency rather than improvising incompatible behavior.
